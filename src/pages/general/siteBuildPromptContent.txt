# LAYER 1 — MASTER SEO/GEO TEMPLATE (v4, SELF-CONTAINED)

This is the reusable template repo. Built once, rebuilt from scratch whenever it
needs updating — never patched in place, never built inside a company-named
folder. Build in `C:\Dev\blueprint-seo-template` (currently empty). No GitHub
remote at build time (attached afterward). No Vercel, no identity beyond
`https://example.com` / `Site Name`. A company site never gets built from this
directly — Layer 2 always starts from a fresh clone.

**Finish line:** `npm run build` (which includes `npm run audit`) and
`npm run cms` succeed locally, and every Section 8 seed step passes.

**Self-contained:** this prompt has no external dependency. Every piece of
third-party-derived code and every cross-system contract is inlined in
Appendix A. Do not look for, reference, or import anything from any other repo.

## 0. THE UPSTREAM SYSTEM (TNV) — contracts only, no code dependency

An external content system ("TNV") produces files this template consumes. The
connection is file hand-off only; there is no runtime link, no shared code, no
import. Everything needed to be compatible is in Appendix A.

- TNV → this CMS: zip of `{slug}.md` + `{slug}.png` (PNG only; collisions
  become `{slug}-2.md` / `{slug}-2.png` and are rejected here because
  frontmatter `slug` won't match the filename — the operator resolves them).
- TNV → this CMS: WTS update JSON, shape A.3.
- This CMS → TNV: confirmation receipt JSON, shape A.4 (manual upload).
- TNV scans the **live published HTML** for the WTS comment markers.

**Real TNV frontmatter (A.2) has these properties — build intake for them:**
- `author: null` → resolve to `DEFAULT_AUTHOR`.
- `draft: true` always → **ignored**; Generate writes `draft: false` unless the
  row's "save as draft" toggle is on.
- Unquoted dates (`date: 2026-08-19`) → coercion helper, always.
- `targetKeyword` may end in ` (no volume data)` → strip that suffix (regex
  `/\s*\(no volume data\)\s*$/i`) before storing, before using as anchor
  text, before using in SERP queries.
- `articleType` values seen: `faq`, `comprehensive`, `howto`, … → schema is a
  free string; only `comprehensive` carries meaning (pillar detection).
- Extra fields present: `slug`, `category`, `keywords`. Accept and preserve
  all of them. Writer never strips unknown keys.
- `pillarKeyword` is a human label (`"Children's Keepsakes & Memory"`), so all
  grouping/matching on `pillarKeyword` and `supportingKeyword` is trimmed and
  case-insensitive.
- Body **begins with a `# H1`** duplicating the title → intake strips one
  leading H1 (error only if a second H1 exists).
- Body has no `## Key Takeaways` → Key Takeaways is a Health **warning**, not
  an intake error.
- Body contains `## Where Things Stand` with both markers → required, error if
  missing or duplicated.

**Credentials** are NOT in this prompt. Create `cms/.env` with
`DATAFORSEO_LOGIN`, `DATAFORSEO_PASSWORD`, `GOOGLE_PAGESPEED_API_KEY`; the
operator pastes values by hand. Commit `cms/.env.example` with documented
empty values (see Section 5). If `cms/.env` is absent at seed time, stop at
Section 8 step 4 and ask.

## 3. CONTENT SCHEMAS — `site/src/content.config.ts`

Astro 5 content layer, `glob()` loaders, `base` paths explicit. Every field
below from day one. No "as previously specified" anywhere — these are the
shapes.

### Dates — fixed decision

- **Stored:** quoted ISO string `"YYYY-MM-DD"` in frontmatter. Schema:
  `z.string().regex(/^\d{4}-\d{2}-\d{2}$/)`.
- **Displayed:** `formatDate()` → `August 20, 2026`. Used on article page,
  grid, team page, "Updated on".
- **Intake coercion (known real bug):** YAML parsers turn unquoted
  `date: 2026-08-14` into a JS `Date` before validation. The CMS intake helper
  handles three cases — correct string, `Date` (`.toISOString().slice(0,10)`),
  and anything `Date.parse` accepts — and the writer **always emits quoted
  strings**. Never assume dates arrive as strings.

### articles

```ts
{
  title: z.string().min(55).max(60),
  description: z.string().min(140).max(160),
  date: isoDate,
  updatedDate: isoDate.optional(),
  author: z.string(),                    // team slug; NOT reference('team')
  tags: z.array(z.string()).min(4).max(6),
  image: image(),                        // site/src/assets/articles/{slug}.{png|jpg|webp}
  imageAlt: z.string().min(10),
  image2: image().optional(), image3: image().optional(),
  draft: z.boolean().default(false),
  robots: z.string().default("index, follow, max-snippet:-1, max-image-preview:large, max-video-preview:-1"),
  schemaType: z.enum(["Article","BlogPosting","NewsArticle"]).default("Article"),
  locale: z.string().default("en_US"),
  twitterCard: z.enum(["summary","summary_large_image"]).default("summary_large_image"),
  // cluster fields — preserved on every save, never stripped

  supportingKeyword: z.string().optional(),
  articleType: z.string().optional(),     // free string; 'comprehensive' = pillar/hub candidate
```

### CMS intake schema — `cms/lib/schema.ts`

Mirrors articles. `author: null` or missing → **resolved to `DEFAULT_AUTHOR`**,
not reported as missing. A null author never reaches the strict Astro schema;
do not loosen the Astro schema.

Body contract at intake:
- **Normalize:** strip one leading `# H1`; strip `(no volume data)` from
  `targetKeyword`; ignore incoming `draft`; resolve null author; coerce dates.
- **Error:** a second H1 anywhere; skipped heading levels; `## Where Things
  Stand` missing, or either WTS marker missing/duplicated; slug field present
  and ≠ filename stem; slug fails `^[a-z0-9]+(?:-[a-z0-9]+)*$`.
- **Warning (Health, not intake):** no `## Key Takeaways` section.

## 4. SITE — LAYOUTS, SEO, PAGES

Astro 5, `output: 'static'`, `trailingSlash: 'always'`, `prefetch: { prefetchAll: false, defaultStrategy: 'hover' }`,
`redirects: {}` seeded empty in `astro.config` (home for future slug changes).

### Sitemap / feeds / robots / llms

- `@astrojs/sitemap`: `filter` excludes `/404`; `serialize` sets `lastmod`
  from `updatedDate || date`. Output is `sitemap-index.xml` only — never
  reference `sitemap.xml`.
- `rss.xml.ts`: **full content** (rendered markdown in `content`), not summary.
  `<link rel="alternate" type="application/rss+xml">` in head.
- `robots.txt.ts`: `Sitemap:` absolute line; per-agent blocks generated from
  `AI_CRAWLERS`; never disallow `/_astro/`.
- `llms.txt.ts` — **an Astro endpoint, not a CMS-written file**. Format:
  `# {SITE_NAME}` → one-paragraph description → `## Articles` grouped by
  `pillarKeyword` (pillar first, then cluster) as `- [title](abs url): description`
  → `## Team` → `## Services`. Published only. Always in sync with the build.
- `[...slug].md.ts` under `ARTICLES_BASE`: serves each published article's raw
  markdown (frontmatter title/description/date/author as a small header, then
  body) at `/{ARTICLES_BASE}/{slug}/index.md`. Cheap, and LLM crawlers use it.

### HTML comment markers — hard gate

Custom remark plugin so both WTS markers survive verbatim into `dist` HTML.
After the first article build, grep `dist` for both markers. If either is
missing, fix the remark config before doing anything else. The audit script
(Section 7) enforces this permanently.

### `BaseLayout.astro`

Owns all meta/OG/JSON-LD. Required `title`/`description` props — throw if
missing. Fallbacks are plain `override || base`, no truncation. `og:description`
byte-identical to meta description when no override. `og:image` is the same
resolved `astro:assets` URL `<Image />` renders, made absolute via `url.ts` —
never a raw dev path. Canonical is always the clean absolute path: query
params never change it. `GOOGLE_SITE_VERIFICATION` meta when non-empty.

**JSON-LD is one `@graph` with stable `@id`s**, assembled by each page and
passed in via the existing generic `jsonLd` prop:

- `Organization` `@id: {SITE_URL}#org` — name, url, logo, sameAs. Every page.
- `WebSite` `@id: {SITE_URL}#website` — publisher → `#org`. Every page.
- `Person` `@id: {SITE_URL}/team/{slug}/#person` — name, jobTitle, description,
  image, sameAs, knowsAbout, url (team page). On article + team pages.
- `BreadcrumbList` on every page below home (the `Breadcrumbs` component and
  this schema render from the same array).
- Article pages: `{schemaType}` with headline, description, image[],
  datePublished, dateModified (always `updatedDate || date`), author → Person
  `@id`, publisher → `#org`, mainEntityOfPage, isPartOf → `#website`, keywords
  (tags), articleSection (pillarKeyword). Plus `FAQPage` when `faqs` non-empty.
- Homepage: `FAQPage` when its `faqs` non-empty — built in `index.astro`, not in
  `BaseLayout` (page-local, same pattern as `ArticleLayout`).
- Service pages: `Service` with provider → `#org`.

OG on articles: `og:type=article`, `article:published_time`,
`article:modified_time`, `article:author`, `article:tag` (one per tag),
`article:section`.

### Article page

`getEntry('team', author)`, build-time throw if missing. `getStaticPaths`
excludes `draft: true` entirely (no route) **in production**; when
`import.meta.env.DEV` is true, drafts are included so the CMS operator can
preview at `localhost:4321` before publishing. Drafts are never in sitemap,
RSS, llms.txt, or `.md` endpoints regardless of mode.

Visible "Updated on {formatDate(updatedDate)}" only when `updatedDate` is a
later calendar day than `date`. `dateModified` in JSON-LD always uses
`updatedDate || date`.

Component order in body: Breadcrumbs → hero `<Image loading="eager" fetchpriority="high">`
(CSS 16:9 + `object-fit: cover`; never strip width/height) → title/byline →
TOC → body (WTS section as authored; Key Takeaways when present) → `FaqBlock`
(`<details>/<summary>`, no JS) → `RelatedLinks` (renders `internalLinks`) →
`Sources` (renders `externalLinks`, `rel="noopener"`, no `nofollow` on
editorial sources) → `AuthorBio` (links to team page). All other images lazy,
`widths`/`sizes` set.

**Article body content (`prose-article`) must render at full container width.**
Do not apply `max-w-article` or any narrowing class to the `.prose-article`
wrapper. In `site/src/styles/global.css`, ensure `.prose-article { width: 100%; }`.

**`RelatedLinks` — open in new tab.** Every `<a>` in `RelatedLinks.astro` must
have `target="_blank" rel="noopener noreferrer"`.

**`AuthorBio` — full-width text in card.** The text `<div>` adjacent to the
photo must carry `class="flex-1 min-w-0"` so it fills available space and does
not collapse. Pass the **full bio string** (not just the first paragraph) from
`ArticleLayout.astro` to `AuthorBio`.

### Shared write path (single implementation, used everywhere)

`validateFrontmatter.ts` → `writeArticle.ts`. Writer: normalizes key order,
quotes dates, preserves cluster fields, writes hero to
`site/src/assets/articles/{slug}.{ext}` and sets the relative `image` path.
Hero valid only if staged this session or paired from the batch — a
pre-existing path string (esp. containing `REPLACE`/`TODO`/`placeholder`) never
counts. Slug drives filename; mismatch is rejected, not corrected.
`MAX_EXTERNAL_LINKS = 5`, `MIN_EXTERNAL_LINKS = 3` — one shared constants file
used by Health and Update. Trim oldest (`addedAt`) first when over cap.

### Add Article — the "7 + 7 → Generate" flow

One screen, two modes sharing all logic:

**Single:** one `.md` (+ optional hero). Field checklist / Missing Fields panel,
collapsed by default with count badges. Author dropdown (from Team) at top of
form next to hero, **pre-selected to `DEFAULT_AUTHOR`**.

**Batch:**
1. **Single unified drop zone** accepting `.md`, `.png`, `.jpg`, `.jpeg`,
   `.webp`, and `.zip` all in one area. The operator drags all files — markdown
   and images together — into this one zone. Wire both the `<input>` and native
   drag-and-drop events (`dragover` → `preventDefault()`, `drop` →
   `dataTransfer.files`) to the same handler so dragging files directly onto
   the div works without clicking the input. A single `.zip` containing both
   is also accepted.
2. Images auto-allocate to rows by filename stem. Matching is
   **case-insensitive** and strips common image suffixes (`-hero`, `-image`,
   `-img`, `-cover`, `-thumb`) before comparing, so `my-article-hero.png`
   matches `my-article.md`. Use this normalization helper:
   ```js
   function normalizedStem(name) {
     return stem(name).replace(/[-_]?(hero|image|img|cover|thumb)$/i, "");
   }
   ```
   Unmatched images listed in an "Unassigned" tray; any row accepts a manual
   drop to override or fill.
3. One row per `.md`: slug, compact status, per-row collapsed Missing Fields.
4. Batch controls: one Author dropdown (pre-selected `DEFAULT_AUTHOR`) applied
   to all rows with per-row override; one fallback hero drop zone applied to
   all rows lacking a matched image.
5. Per-row validation failures (title range, alt length, body contract) stay
   visible after batch-apply — batch controls only cover author/image.
6. **`hasImage` flag:** set `true` on a row only when a per-slug matched image
   exists for that specific row. A fallback/batch-hero does not set
   `hasImage = true` on individual rows — the Generate button accounts for it
   separately:
   ```js
   function refreshGenerate() {
     if (state.mode === "single") {
       $("generate").disabled = !(row && row.ok && (state.single.hero || row.hasImage));
     } else {
       const fallback = $("batch-hero-all").files.length > 0;
       $("generate").disabled = !(
         state.batch.rows.length &&
         state.batch.rows.every((r) => r.ok && (r.hasImage || fallback))
       );
     }
   }
   ```
7. **"Generate"** enabled when every row is valid (errors = 0) and every row
   has either a matched image or the fallback hero is set. Sequential, never
   parallel. Progress "Generating 4 of 10: {slug}". Live per-row status
   (pending → ✓ / ✗ with reason); one failure does not stop the rest.
8. **`draft: false` by default** — Generate publishes. Per-row "save as draft"
   toggle available. Session banner reminds that commit/push/deploy is what
   actually makes it live.
9. Warn (not block) when a hero is <1200px wide or >1MB.

`cms/lib/providers/dataforseo.js` (only `serpResults` is needed; keep the
helpers exactly as written)
```javascript
import { markProviderFailure, markProviderSuccess } from './health.js'

const TIMEOUT_MS = 30000
const LOCATION_CODE = 2840
const LANGUAGE_CODE = 'en'

function unavailable(reason) {
  return { available: false, provider: 'dataforseo', reason: String(reason || 'unavailable') }
}

function authHeader() {
  const login = process.env.DATAFORSEO_LOGIN
  const password = process.env.DATAFORSEO_PASSWORD
  if (!login || !password) return null
  return `Basic ${Buffer.from(`${login}:${password}`).toString('base64')}`
}

async function dfsPost(path, task) {
  const auth = authHeader()
  if (!auth) return unavailable('DATAFORSEO_LOGIN/PASSWORD not configured')

  const controller = new AbortController()
  const timer = setTimeout(() => controller.abort(), TIMEOUT_MS)
  try {
    const res = await fetch(`https://api.dataforseo.com${path}`, {
      method: 'POST',
      headers: { Authorization: auth, 'Content-Type': 'application/json' },
      body: JSON.stringify([task]),
      signal: controller.signal,
    })
    const data = await res.json().catch(() => null)
    if (!res.ok) {
      markProviderFailure('dataforseo', `HTTP ${res.status}`)
      return unavailable(`DataForSEO HTTP ${res.status}`)
    }
    if (!data || data.status_code !== 20000) {
      markProviderFailure('dataforseo', data?.status_message || 'top-level error')
      return unavailable(data?.status_message || `status_code ${data?.status_code}`)
    }
    const taskResult = Array.isArray(data.tasks) ? data.tasks[0] : null
    if (!taskResult || taskResult.status_code !== 20000) {
      markProviderFailure('dataforseo', taskResult?.status_message || 'task error')
      return unavailable(taskResult?.status_message || `task status ${taskResult?.status_code}`)
    }
    markProviderSuccess('dataforseo')
    return { available: true, provider: 'dataforseo', taskResult }
  } catch (err) {
    const msg = err?.name === 'AbortError' ? 'DataForSEO request timed out' : err?.message
    markProviderFailure('dataforseo', msg)
    return unavailable(msg)
  } finally {
    clearTimeout(timer)
  }
}

export async function serpResults({ keyword, depth = 10 }) {
  const phrase = String(keyword || '').trim()
  if (!phrase) return unavailable('keyword is required')

  const result = await dfsPost('/v3/serp/google/organic/live/regular', {
    keyword: phrase,
    location_code: LOCATION_CODE,
    language_code: LANGUAGE_CODE,
    depth: Math.min(Number(depth) || 10, 50),
  })
  if (!result.available) return result

  const result0 = Array.isArray(result.taskResult.result) ? result.taskResult.result[0] : null
  const items = Array.isArray(result0?.items) ? result0.items : []

  return {
    available: true,
    provider: 'dataforseo',
    report: 'serp_results',
    keyword: phrase,
    items: items
      .filter((item) => item?.type === 'organic' || item?.url)
      .slice(0, 20)
      .map((item) => ({
        type: item.type || 'organic',
        rank: item.rank_absolute ?? item.rank_group ?? null,
        title: item.title ?? null,
        url: item.url ?? null,
        domain: item.domain ?? null,
        description: item.description ?? null,
      })),
  }
}
```
Consume only the normalized shape: `{available, reason?}` or
`{available: true, items: [{type, rank, title, url, domain, description}]}`.

`cms/lib/providers/pagespeed.js`
```javascript
const PAGESPEED_ENDPOINT = 'https://www.googleapis.com/pagespeedonline/v5/runPagespeed'
const CATEGORIES = ['performance', 'accessibility', 'best-practices', 'seo']
const CATEGORY_KEYS = { performance: 'performance', accessibility: 'accessibility', 'best-practices': 'bestPractices', seo: 'seo' }

function scoreTo100(raw) {
  if (typeof raw !== 'number' || Number.isNaN(raw)) return null
  return Math.round(raw * 100)
}

function extractCoreWebVitals(loadingExperience) {
  if (!loadingExperience || typeof loadingExperience !== 'object') return null
  const metrics = loadingExperience.metrics || {}
  const pick = (key) => {
    const m = metrics[key]
    if (!m) return null
    return { percentile: m.percentile ?? null, category: m.category || null }
  }
  return {
    overallCategory: loadingExperience.overall_category || null,
    id: loadingExperience.id || null,
    metrics: {
      lcp: pick('LARGEST_CONTENTFUL_PAINT_MS'),
      cls: pick('CUMULATIVE_LAYOUT_SHIFT_SCORE'),
      inp: pick('INTERACTION_TO_NEXT_PAINT'),
      fcp: pick('FIRST_CONTENTFUL_PAINT_MS'),
      ttfb: pick('EXPERIMENTAL_TIME_TO_FIRST_BYTE'),
    },
  }
}

/** Run PageSpeed Insights for one strategy (mobile | desktop). Soft-fails. */
export async function runPagespeed({ url, strategy, apiKey, signal }) {
  if (!apiKey) {
    return { ok: false, error: 'GOOGLE_PAGESPEED_API_KEY is not configured', strategy }
  }
  const params = new URLSearchParams({ url, strategy, key: apiKey })
  for (const category of CATEGORIES) params.append('category', category)

  try {
    const res = await fetch(`${PAGESPEED_ENDPOINT}?${params.toString()}`, {
      method: 'GET', signal, headers: { Accept: 'application/json' },
    })
    const data = await res.json().catch(() => ({}))
    if (!res.ok) {
      const message = data?.error?.message || data?.error?.errors?.[0]?.message || `PageSpeed API error (${res.status})`
      return { ok: false, error: message, strategy, status: res.status }
    }
    const lighthouse = data.lighthouseResult || {}
    const categories = lighthouse.categories || {}
    const scores = {}
    for (const cat of CATEGORIES) scores[CATEGORY_KEYS[cat]] = scoreTo100(categories[cat]?.score)
    return {
      ok: true,
      strategy,
      scores,
      coreWebVitals: {
        url: extractCoreWebVitals(data.loadingExperience),
        origin: extractCoreWebVitals(data.originLoadingExperience),
      },
      fetchTime: lighthouse.fetchTime || null,
      finalUrl: lighthouse.finalUrl || data.id || url,
    }
  } catch (err) {
    if (err?.name === 'AbortError') return { ok: false, error: 'PageSpeed request timed out', strategy }
    return { ok: false, error: err?.message || 'PageSpeed request failed', strategy }
  }
}

/** Panel: mobile + desktop, sequential to avoid rate limits. */
export async function runPagespeedPanel({ siteUrl, signal }) {
  const apiKey = process.env.GOOGLE_PAGESPEED_API_KEY || ''
  if (!apiKey) {
    return { ok: false, error: 'GOOGLE_PAGESPEED_API_KEY is not configured', panel: 'pagespeed' }
  }
  try {
    const mobile = await runPagespeed({ url: siteUrl, strategy: 'mobile', apiKey, signal })
    const desktop = await runPagespeed({ url: siteUrl, strategy: 'desktop', apiKey, signal })
    const ok = Boolean(mobile?.ok || desktop?.ok)
    return {
      ok, panel: 'pagespeed', siteUrl, mobile, desktop,
      error: ok ? null : mobile?.error || desktop?.error || 'PageSpeed checks failed',
    }
  } catch (err) {
    if (err?.name === 'AbortError') return { ok: false, error: 'PageSpeed panel timed out', panel: 'pagespeed' }
    return { ok: false, error: err?.message || 'PageSpeed panel failed', panel: 'pagespeed' }
  }
}
```
Health's three Speed states map to: `error === 'GOOGLE_PAGESPEED_API_KEY is not configured'`
→ not configured; `ok: false` with `status` or a timeout message → scan
failed; `ok: true` → success. Do not inspect `lighthouseResult.runtimeError`.

### A.4 Confirmation receipt (this CMS → TNV)

TNV's parser rules:
- Accepts a bare array, or an object whose `receipts` / `confirmed` /
  `articles` is an array. **Emit a bare array.**
- Per entry: `slug` (required, non-empty); `confirmedDate` (required,
  `^\d{4}-\d{2}-\d{2}$`; TNV also accepts `newUpdatedDate` / `updatedDate`
  as fallbacks — emit `confirmedDate`); `confirmedAt` (optional string, read
  but not persisted).
- Duplicate slugs are dropped after the first. Entries failing validation are
  silently skipped, so format matters.
- TNV persists `confirmedDate` as the article's updated date.

Emit exactly:
```json
[
  { "slug": "the-slug", "confirmedDate": "2026-08-20", "confirmedAt": "2026-08-20T17:42:11.000Z" }
]
```
